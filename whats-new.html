Latest release · Build 32

Quality recovery and real engine upgrades.

Build 32 upgrades the five targeted flagship processing paths while retaining fallbacks: BiRefNet-lite background removal, PDF.js 6.4.299 editor/rendering, structured PDF-to-Word with shared OCR, LaMa watermark inpainting, and PP-OCRv5 OCR. It also repairs the shared six-tool layout layer and QR presentation.

Background Remover

BiRefNet is now attempted as the primary browser ML segmentation path, with existing local/portrait processing retained as fallback.

PDF Editor

PDF.js 6.4.299 now drives PDF rendering, with pdf-lib/fontkit-aware export and controlled font fallback for unsupported embedded/subset fonts.

PDF to Word

Text PDFs keep structured reconstruction; scanned pages now attempt the shared PP-OCRv5 OCR core before the safe page-image fallback.

Watermark Remover

LaMa ONNX is now the primary masked-region reconstruction path, using browser WebGPU where available and WASM fallback, with the previous local reconstruction retained as emergency fallback.

OCR Studio

PP-OCRv5 is attempted first in the browser, with the previous Tesseract OCR route retained as fallback.

Six-tool layout repair

The shared Build 30 flagship pages now receive a defensive Build 32 layout layer for normal logo sizing and immediate workspace placement.

QR presentation

The desktop QR uses the available strip height more effectively, while the complete QR strip remains removed on mobile.

Stable fallbacks preserved

New ML paths do not remove the previous local fallback routes, so unsupported browsers can still attempt the established processing path.

Production package cleanup

Historical build and audit text files are excluded from the deployable package.
